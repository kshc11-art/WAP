## D0 — 저장소 작업보다 먼저 확인할 것

구조 이야기 이전에, **지금 회사 PC에서 돌고 있는 코드에 업무 사고로 이어질 수 있는 동작이 두 개** 있다.
저장소를 어떻게 만들든 이건 먼저 확인해야 한다.

### D0-1. `core-recon`의 네트워크 훅이 쓰기 요청을 "가짜 성공"으로 삼킬 수 있다

- `core-recon`은 `@run-at document-start`로 krisstar / gw / bpm **전 화면**에서 뜬다.
- `installHooks()`가 로드 즉시 무조건 실행되어(`:1923`) `fetch`와 `XHR`을 교체한다(`:1741-1747`, `:1775-1783`).
- 쓰기로 분류된 요청은 **HTTP 200 + `{"errorCode":"KRISS_RECON_BLOCKED","data":[]}`** 를 돌려준다(`:1714`).
  즉 호출한 쪽에서 보면 성공이다.
- 이 차단은 정찰 세션 중에만 동작하는데, 세션 TTL이 **2시간**이고 GM 저장소에 있어
  **탭·브라우저를 다시 열어도 유지된다**(`:104`, `:1218-1222`).
- 한편 `portal-dashboard`는 선행조사 요청을 보내고 `r.ok`(=200)만 확인한 뒤
  "요청을 생성했습니다" 토스트를 띄운다(`:1344-1351`, `:1336`). `errorCode`를 보지 않는다.

**결과**: 정찰 세션이 켜진 줄 모르는 상태에서 대시보드로 선행조사를 요청하면,
화면은 성공이라고 말하고 서버에는 아무것도 가지 않는다. 최대 2시간, 재시작을 넘어 지속된다.

> **확인할 것**: 지금 `core-recon`이 항상 켜져 있는가?
> 켜져 있다면 **정찰할 때만 켜는 것**으로 즉시 바꾸는 것을 권합니다.
> (근본 수정은 ① 훅 설치를 세션 시작 시점으로 늦추기 ② 차단 시 가짜 200 대신 명시적 실패를 돌려주기
> ③ 호출하는 쪽이 `errorCode`를 확인하게 하기 — 셋 다 별도 Issue로 다룰 일입니다.)

### D0-2. `annualfee-expense`가 확인 다이얼로그를 자동으로 누르는데 정지 수단이 없다

- 다이얼로그 본문이 `/하시겠습니까|저장하시겠습니까/`이면 확인 버튼을 찾아(`:1756-1760`)
  **60ms 폴링으로 발견 즉시 클릭**한다(`:1764-1783`). 저장 버튼을 누르면 자동 무장된다(`:1785-1793`).
- 단축키 `4`가 결재 최종확인을 직접 클릭하고(`:2571-2582`), 승인 버튼도 직접 클릭한다(`:2530-2537`).
- 이 파일에 `Alt+Shift+X` 핸들러 **0건**, panic/kill류 API **0건**.
  `@description`에는 "Tampermonkey 하위 메뉴 숨김"이 명시돼 있다.

**결과**: 사람의 마지막 확인 단계를 제거하는 코드인데, 그 코드를 끄는 수단이 파일 안에 없다.

> **확인할 것**: 이 스크립트가 의도대로만 동작하는지, 그리고 급할 때 어떻게 멈추는지.
> 규칙으로 삼을 것: **쓰기·승인 경로를 건드리는 스크립트는 킬스위치 없이 반입 불가.**

## 1. 정체성 — 파일명을 바꾸고 싶다는 요청의 실제 지점

파일명 변경은 두 개의 서로 다른 문제이고, 어려운 쪽은 두 번째다.

**(A) git 쪽 — 문제가 아니다.** git은 내용으로 rename을 추적한다. 파일명을 바꿔도 이력은 이어진다.

**(B) Tampermonkey 쪽 — 여기가 진짜다.**
TM은 설치된 스크립트를 `@namespace` + `@name` 쌍으로 식별하고 GM 저장 데이터를 거기에 묶는다.
`@name`이 바뀐 파일을 **"새 스크립트로 설치"** 하면 별개 항목이 되어
GM 데이터가 갈라지고, 같은 `@match`에 두 벌이 동시에 뜬다.

그런데 실측상 `@namespace`가 이미 중복이다.

| namespace 실측값 | 스크립트 수 |
|---|---|
| `https://krisstar.kriss.re.kr/` | 4 |
| `kriss-ipms-enhancement` | 3 |
| `kriss.internal.console` | 3 |
| `kriss.krisstar.tools` | 2 |

**시사**: 이름을 정리하는 작업은 "예쁘게 만들기"가 아니라 **식별자 충돌을 푸는 작업**이다.
그리고 저장소가 줄여줄 수 있는 것은 이력 추적이지 Tampermonkey에 다시 붙여넣는 횟수가 아니다.
이 점은 과장하지 않는 것이 낫다.

**GM 데이터가 실제로 쌓여 있는 스크립트 3개**(이름 변경 시 유실 위험):
`core-recon`(누적 지식DB), `portal-dashboard`(위젯 배치), `mail-gwx`(라벨·임시저장).

## 2. 충돌 — 구조보다 먼저 있는 실제 위험

### 2-1. 한 화면에 여러 스크립트가 동시에 뜬다
`*://*.kriss.re.kr/*` 광역 match를 쓰는 스크립트가 4개
(`ipms-compare-paper`, `ipms-compare-iprs`, `portal-popup-manager`, `ipms-input-helper`).
여기에 `krisstar.kriss.re.kr/*` 계열이 겹쳐, 포털 메인에서만 **11~13개가 동시 실행**된다.

### 2-2. 두 대조 Helper가 같은 전역 가드를 서로 뺏는다
둘 다 `if (window.__krissDlIntercept) return; window.__krissDlIntercept = true;` 로 같은 전역 키를 선점한다
(`ipms-compare-paper:910`, `ipms-compare-iprs:822`). 나중에 뜬 쪽이 조용히 죽는다.

### 2-3. 긴급복구가 성립하지 않는다
브리프 6-3은 `Alt+Shift+X`를 "탬퍼몽키 전체 비활성화"로 정의한다. 실제로는:
- `Alt+Shift+X` 핸들러가 있는 파일: **3개**(`mail-gwx:6471`, `portal-dashboard:3683`, `ipms-detail-keys:96`) — 각자 자기만 끈다.
- 삽입 요소 표식 접두어가 **9종**으로 갈라져 있어 일괄 제거가 불가능하다.
- 나머지 스크립트(통계추출·입력 Helper·보조원장·테마 등)에는 킬스위치가 **없다**.
- 저장소 문서가 규범으로 적어둔 `const ENABLED` 패턴을 지키는 파일: **0/17**.

### 2-4. 쓰기 차단 목록이 스크립트마다 다르다
`console-host:196-197`의 차단 정규식은 `create|update|save|delete|insert|modify|approve|reject|regist` 이고,
`core-recon:134-135`는 여기에 `receipt·submit·send·issue·confirm·cancel·return·upload` 등을 더 포함한다.
즉 콘솔 쪽은 **접수·제출·발행·확인·취소 계열을 차단하지 못한다.**
브리프는 이 영역을 "실제 회계·예산 트랜잭션 — 절대 호출 금지"로 못박고 있다.

## 3. 사실(fact)의 분열 — 이 프로젝트의 진짜 병

중복 코드는 생각보다 적다. **같은 사실이 여러 벌로 갈라진 것**이 훨씬 심각하다.

같은 화면의 같은 상태코드가 스크립트마다 다르게 번역된다:

| 화면·코드 | `portal-dashboard` | `ipms-palette` |
|---|---|---|
| 청구서 `03` | 검토준비중 (`:977`) | 임시저장 (`:265`) |
| 청구서 `04` | 검토중 | 검토실행 (`:266`) |
| 등록 완료판정 | `['07','12']` (`:839`) | `07~12` 전부 완료 (`:238-241`) |

게다가 등록 완료코드는 **세 번 뒤집혔다** — 브리프(`:681`) `12` → 대시보드 주석(`:726`) `07·09` → 대시보드 상수(`:839`) `07·12`.
`apvStat` 사전은 **5벌**이고, 상태 필드 이름 자체도 화면마다 다르다
(`apvStat` / `apvStatNm` / `aplyApvStat` / `rqstApvStat` / `cmplRqstApvStat`).

**시사**: 두 스크립트가 같은 건을 나란히 보여주면 서로 다른 진행상태를 말한다.
이것만이 실제로 **업무 오답**을 만든다. 그래서 저장소의 최우선 공용 자산은
유틸 함수가 아니라 **상태코드 계약 데이터**다.

## 4. 중복 코드 — 생각보다 적고, 한 군데에 몰려 있다

- `ipms-compare-paper:128-956` ↔ `ipms-compare-iprs:40-868`: **831줄이 바이트 단위로 동일**.
  두 파일의 주석이 *"수정 시 양쪽 모두 교체할 것"* 이라고 사람에게 지시하고 있다 —
  코딩을 하지 않는 사용자에게는 이미 실패한 절차다.

- 전체 저장소에서 제거 가능한 중복은 약 **1,270줄(3.6%)**.

**시사**: 줄 수를 줄이는 것은 목표가 아니다. 없앨 가치가 있는 중복은 위 831줄 하나뿐이고,
그것도 "바이트를 없애기" 위해서가 아니라 **사람이 손으로 맞추는 절차를 없애기** 위해서다.

## 8. 이미 있는데 안 쓰이는 것

- **`core-recon`은 이미 Adapter의 입력 스키마를 생산하고 있다.**
  `buildPaletteSpec`이 `paletteAdapters = {list, search, open, detail, workflow, commands}`를 만들고(`:3520`),
  각 항목이 `endpoint` / `response.dataPath` / `response.fields` / `requestMappings`를 갖는다(`:3441-3443`).
  상태코드는 화면 `<select>`에서 실측 수집하고(`probeStatusCodes:4526`),
  저장 전 `maskDeep`(`:323`)으로 민감값을 마스킹한다.
  **그런데 이 산출물을 참조하는 파일은 자기 자신 1개뿐이다.**
- **Python 브리지도 이미 돌고 있다.** `annualfee-expense`에 `@connect 127.0.0.1`(`:11-12`),
  `DEFAULT_BRIDGE='http://127.0.0.1:8765'`(`:39`), `/api/manifest`·`/api/file/`·`/api/status`(`:261-288`),
  그리고 주경로인 File System Access API + `<결과폴더>/템퍼몽키용/manifest.json` 계약(`:66-67`, `:184-195`)이 있다.

**그런데 제가 앞서 커밋한 `ENGINEERING_RULES.md §8`은 이 localhost 방식을 금지했고,
데이터 흐름도 실제와 반대로 적혀 있었다**(규칙은 TM→Python, 실제는 Python이 만들고 TM이 읽는다).
규칙대로 따르면 AI가 목표 (2)의 유일한 실작동 경로를 지운다. 이번에 고쳤다.

## 9. 디지털트윈 — 정의를 바꿔야 한다

대상 화면 자체가 개인정보 덩어리다(신청목록 3,691건 · 업무요청 5,136건 · 마스터 67컬럼,
필드에 주발명자 실명·사번·내선·이메일·금액).
그리고 "구조만 담겠다"는 의도와 무관하게 실데이터가 새는 경로는 **이미 두 번 실증됐다**(§7).
git은 한 번 커밋되면 히스토리 재작성 없이는 지울 수 없다.

**따라서 "화면 원본 저장"이 아니라 "화면 골격 저장"으로 정의를 바꾼다.**
지울 것 목록이 아니라 **남길 것 목록(화이트리스트)** 으로 해야 한다 —
`tag` / `id` / `name` / `type` / `class` / 컬럼순서 / 그리드ID 만 남기고
텍스트 노드·input value·select option 텍스트·href 쿼리스트링·title/alt는 전부 제거.
**스크린샷 이미지는 아예 금지** — 마스킹을 검증할 방법이 없다.

법령 쪽은 반대로 문제가 없다. 대한민국 법령의 조문은 저작권법 제7조에 따라 보호 대상이 아니므로
전문 보관에 제약이 없다(단 **판례·해설·주석서는 다르다** — 링크와 인용만).
용량도 특허·실용신안·디자인·상표 관련 법령 전체가 텍스트 수 MB 수준이다.
