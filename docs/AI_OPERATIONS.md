# Claude와 GPT 함께 쓰기

관찰에서 출발한다.

> "Claude는 확실히 방향 및 검토를 잘하는 것 같고,
> GPT는 토큰 제약이 덜하고 많은 파일을 한 번에 볼 수 있는 장점이 있지만 배가 산으로 갈 때가 있다."

이 관찰이 맞다는 전제에서 설계한다. 핵심은 **역할 분담을 문서에 적는 것이 아니다.**
적어두면 안 지켜진다. **각자에게 줄 입력을 저장소가 만들어 주고, 일탈은 사후에 기계가 잡는다.**

---

## 1. 세 가지를 구분해야 한다

혼동하기 쉬운 지점부터 정리한다. 셋은 읽는 파일이 다르다.

| | 무엇 | 저장소를 읽는가 | 근거 파일 |
|---|---|---|---|
| **ChatGPT 웹 채팅** | 붙여넣은 파일만 본다 | ❌ **아무것도 안 읽는다** | 사람이 붙여넣는 `state/brief/<slug>.md` |
| **Codex** (GitHub 연동) | PR을 리뷰한다 | ✅ | `AGENTS.md` |
| **Claude Code** | 저장소에서 직접 작업한다 | ✅ | `CLAUDE.md` |

**가장 흔한 실수**: `AGENTS.md`를 써두면 ChatGPT 웹 채팅이 읽을 거라고 기대하는 것.
읽지 않는다. 웹 채팅에 규칙을 전달하는 유일한 방법은 **매번 붙여넣는 것**이고,
그래서 저장소가 그 붙여넣을 것을 자동으로 만들어야 한다.

---

## 2. 역할 분담 — 작업 유형으로

"설계는 Claude, 구현은 GPT" 같은 추상적 분담은 실제로는 안 지켜진다. 작업 유형으로 나눈다.

### GPT에게 주는 것 — 파일 하나를 통째로 고치는 일

- 6,505줄짜리 한 파일 안에서의 기능 추가·수정·버그 픽스
- 한 파일 전체를 읽어야 판단되는 일 (섹션 간 영향, 중복 로직 정리)
- 대량의 반복적 변환 (변경이력 주석 정리, 문자열 일괄 치환)
- **응답은 항상 파일 전문으로** 받는다. 부분 diff를 받으면 붙여넣다가 파일이 잘린다.

GPT가 강한 이유는 그대로다 — 한 번에 많이 보고, 길게 뱉는다.
그리고 사용자는 실제로 GPT에게 코드를 짜게 한다. **그걸 막는 설계는 실패한다.**

### Claude에게 주는 것 — 여러 파일에 걸치거나, 판단이 필요한 일

- 저장소 구조·계약 설계 (`contracts/`, `rules/`)
- 검사기·자동화 (`tools/`, `.github/workflows/`)
- 여러 스크립트에 걸친 문제 진단 (충돌, 상태코드 분열, 중복)
- 반입본 리뷰, 위험 판정, "이걸 해도 되는가" 판단
- Python 쪽 (`python/`)

**Claude는 원칙적으로 `scripts/` 안의 코드 파일을 직접 고치지 않는다.**
고치면 사용자가 외부에서 작업 중인 사본과 즉시 충돌한다.
거대 파일을 볼 때는 전체 대신 `state/outline/<slug>.md`(섹션 지도)로 접근한다.

### 사람이 하는 것 — 아무도 대신 못 한다

- 내부망 실제 동작 확인 (`needs-internal-test`)
- 반출 가능 여부 판단 (내부 호스트명·화면ID = 가드의 `WARN` 항목)
- 상태코드 계약의 최종 확정 (어느 쪽이 맞는지는 업무를 아는 사람만 안다)

## 3. "배가 산으로 가는 것"을 막는 방법

부탁으로 막지 않는다. **입력을 좁히고, 일탈을 사후에 검출한다.**

### 3-1. 입력을 좁힌다 — `state/brief/<slug>.md`

저장소가 스크립트마다 A4 한 장짜리 지시서를 자동 생성한다. 사용자는 이것과 파일 하나만 GPT에 붙여넣는다.

```markdown
# <표시명>  (slug: mail-gwx)

## 절대 바꾸지 않는 것
- @namespace: wap.mail-gwx        ← 이 줄을 바꾸면 Tampermonkey가 별개 스크립트로 봅니다
- 파일 맨 위 /* WAP-ID */ 블록     ← 킬스위치입니다. 지우지 마세요
- /* WAP-INLINE ... */ 마커 쌍     ← 공유 코드 경계입니다

## 이 스크립트가 소유한 자원 (다른 것을 새로 만들지 마세요)
- DOM 접두어:   wap-mail-gwx-
- 저장소 키:    wap:mail-gwx:
- 단축키:       Alt+Shift+X, Alt+M
- z-index 대역: 9200-9299

## 같은 화면에 함께 뜨는 스크립트와 그들이 이미 쓰는 것
- portal-dashboard : window.__PD, data-pd-*, Alt+Shift+E
- ipms-palette     : Ctrl+Space, z-index 9400대
  → 위 이름·키를 쓰지 마세요.

## 이 파일이 부르는 API와 계약 상태
- /pms/.../selectXxxList.json   confidence: measured (2026-08 확인)
- /pms/.../selectYyy.json       confidence: inferred  ← 추정입니다. 사실로 단정하지 마세요

## 섹션 지도
(자동 생성)

## 응답 규칙
- 이 파일 하나만 수정합니다. 다른 파일을 만들지 않습니다.
- 외부 CDN @require 를 추가하지 않습니다.
- 새 전역 변수·새 단축키·새 z-index 를 도입하지 않습니다.
- 응답은 파일 전문으로 줍니다. 생략하거나 "…이하 동일" 로 쓰지 않습니다.
- @version 을 올립니다.
```

이 지시서의 값은 **전부 `contracts/scripts.yaml`과 `state/`에서 생성된다.** 사람이 쓰는 게 아니다.

### 3-2. 일탈을 검출한다 — 반입 게이트

지시를 어겨도 괜찮다. 커밋 직후 기계가 잡는다.

| GPT가 하기 쉬운 일탈 | 무엇이 잡는가 |
|---|---|
| `@namespace`를 "정리"하면서 바꿈 | **차단** (구조 계약 파손) |
| 킬스위치 블록을 "불필요한 코드"라고 지움 | **차단** (프리앰블 부재) |
| 인라인 마커를 정리해 버림 | **차단** (마커 쌍 불균형) |
| 파일이 중간에 잘림 | **차단** (`node --check`) |
| 실명·사번을 예시로 넣음 | **차단** (`guard.py`) |
| 외부 CDN `@require` 추가 | 배포본 미갱신 |
| 계약에 없는 새 엔드포인트 호출 | 배포본 미갱신 |
| `@version` 안 올림 | 봇이 자동으로 patch 증가 |

부탁이 아니라 사후 검출이므로 **GPT의 성향에 의존하지 않는다.**

### 3-3. 파일을 쪼개거나 합칠 때 — 사전 예약

GPT에게 "이 파일을 셋으로 쪼개줘"라고 하면, 돌아온 세 파일이 모두 같은 slug를 주장한다.
반입기가 순서대로 덮어쓰면 마지막 하나만 남고 나머지는 **에러 없이 사라진다.**

규칙 두 개로 막는다.

1. **반입기는 절대 덮어쓰기로 충돌을 해결하지 않는다.** 한 배치에 같은 slug가 2회 이상 나오면
   전부 `inbox/`에 남기고 하드 실패시킨다.
2. **분할·합병은 사후 반입이 아니라 사전 예약이다.** 먼저 `contracts/scripts.yaml`에
   새 slug를 등록하고(합병이면 `supersedes: [옛slug]`), 그 다음에 GPT에게 시킨다.
   `supersedes`가 있으면 새 스크립트가 부팅 시 옛 스크립트를 스스로 비활성화하고
   "이 스크립트는 통합되었습니다 — Tampermonkey에서 삭제하세요" 배너를 띄운다.
   합병이 브라우저 안에서 자기집행된다.

## 4. 둘이 같은 파일을 건드렸을 때

가장 조용한 사고다. GPT가 전면 교체한 파일을 반입하면 **git에서 충돌이 나지 않으므로**
그 사이 Claude가 넣은 수정이 경고 한 줄 없이 사라진다.

**출처 스탬프로 막는다.** 봇이 프리앰블 안에 기준 커밋을 함께 굽는다.

```js
var WAP_ID = 'mail-gwx', WAP_VER = '1.3.8', WAP_BASE = 'a1b2c3d';
```

반입기가 `WAP_BASE` 이후 저장소에 그 파일에 대한 커밋이 있는지 확인하고,
있으면 **빠른 덮어쓰기를 거부**한다. 대신 반입본을 브랜치에 올리고
"기준 이후 저장소 변경 3건 — 어느 쪽을 살릴지 정하세요"를 이슈로 남긴다.

**봇은 절대 병합하지 않는다.** 매일 업무에 쓰이는 코드에서 자동 병합은 금지다.

## 5. 리뷰 — 전면 교체 PR을 어떻게 보는가

파일 하나가 통째로 돌아오면 diff가 "6,505줄 삭제 / 8,000줄 추가"가 된다.
리뷰 도구에 들어가지도 않고, 들어가도 신호 대 잡음비가 0이다.
그 상태로 "AI 리뷰 통과"를 요구하면 형식적 통과만 만들어낸다.

**PR을 두 종류로 나눈다.**

| | 판정 | 리뷰 방식 |
|---|---|---|
| **부분 수정** | 변경량이 원본의 30% 미만 | Codex diff 리뷰 (`AGENTS.md` 기준) |
| **전면 교체** | 30% 이상, 또는 섹션 신설·삭제 | **diff 리뷰 요구를 해제**하고 스모크 체크리스트로 대체 |

전면 교체 PR에는 봇이 `contracts/scripts.yaml`에서 **스모크 체크리스트를 자동 생성**해 본문에 붙인다 —
"이 스크립트가 소유한 화면 3곳에서 ① 목록이 뜨는가 ② 주요 기능이 열리고 닫히는가
③ 다른 스크립트가 죽지 않았는가". 사람이 회사 PC에서 이것만 확인한다.

형식적으로 통과되는 게이트는 없는 게 낫다.

## 6. 실제 하루

```
① 불편한 것 발견
      ↓
② Claude에게: "이거 어느 스크립트 문제야? 어떻게 접근해야 해?"
      → 진단 · 접근 방향 · 위험 지점.  필요하면 Issue 초안까지
      ↓
③ state/brief/<slug>.md + scripts/<slug>.user.js 를 GPT에 붙여넣기
      → 파일 전문을 받음
      ↓
④ inbox/ 에 넣고 커밋
      → 봇: 정규화 · 검사 · 색인 갱신 · scripts/ 에 커밋
      ↓
⑤ 검사에 걸린 게 있으면 Claude에게 그 이슈를 넘김
      → 킬스위치 복구, 마커 복구, 계약 갱신은 Claude 쪽 일
      ↓
⑥ scripts/<slug>.user.js 를 Tampermonkey 편집기에서 덮어쓰기
      → needs-internal-test 확인
      ↓
⑦ 통과하면 끝. 실패하면 ③으로
```

②를 건너뛰고 바로 GPT로 가도 된다. 다만 ②가 있으면 ③의 지시서가 정확해진다.

## 7. 근거 파일을 어떻게 나눌 것인가

```
                  ENGINEERING_RULES.md      ← 규칙의 유일한 원본
                    ↑        ↑        ↑
              CLAUDE.md  AGENTS.md  state/brief/<slug>.md
                 ↑           ↑            ↑
            Claude Code    Codex     ChatGPT 웹 (사람이 붙여넣음)

                  contracts/                ← 사실의 유일한 원본
                    ↑        ↑
              세 AI 전부가 같은 사실을 본다
```

**규칙이 바뀌면 `ENGINEERING_RULES.md` 하나만 고친다.** 나머지는 참조한다.

`contracts/`의 모든 레코드는 **`confidence`를 필수로 갖는다**:

| 값 | 뜻 |
|---|---|
| `measured` | 실제로 확인함 (`verifiedAt`·`verifiedOn` 필수) |
| `inferred` | 코드나 문서에서 추정 |
| `unknown` | 모름 |
| `conflict` | **여러 출처가 서로 다름 — 아직 해결되지 않음** |

`conflict` 등급이 중요하다. 등록 완료코드가 세 번 뒤집히고 청구서 `03`이 두 가지로 갈린 상태에서
([FINDINGS §3](FINDINGS.md)), 계약의 첫 성과는 모순을 **해결**하는 게 아니라
한 표에 올려 **드러내는** 것이다. 해결을 전제하면 계약 작성이 시작조차 안 된다.

그리고 이 등급이 "추정을 사실로 단정하지 마라"를 문장이 아니라 **데이터로** 전달한다.
두 AI 모두 `inferred`를 보면 그것이 추정임을 안다.

## 8. 요약

| 원칙 | 이유 |
|---|---|
| GPT를 막지 않는다 | 막는 설계는 우회된다 |
| GPT의 **입력**을 저장소가 만든다 | 부탁은 안 지켜지고 입력은 지켜진다 |
| 일탈은 **사후 검출**한다 | 성향에 의존하지 않는다 |
| Claude는 `scripts/`를 직접 안 고친다 | 외부 작업본과 충돌하면 저장소가 버려진다 |
| 웹 채팅은 아무것도 안 읽는다 | 그래서 지시서를 자동 생성한다 |
| 차단은 4개, 나머지는 알림 | 5개가 되는 날 우회가 시작된다 |
| 전면 교체는 diff 리뷰를 요구하지 않는다 | 형식적 통과보다 스모크 체크가 낫다 |
| 최종 판정은 사람이 내부망에서 | 두 AI 모두 사내망을 볼 수 없다 |
