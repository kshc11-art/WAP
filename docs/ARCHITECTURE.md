# 저장소 구조

실측([FINDINGS.md](FINDINGS.md))에 비추어 다시 설계한 구조다.
운영 절차(브랜치·PR·라벨)는 [GITHUB_OPERATIONS.md](GITHUB_OPERATIONS.md), AI 분담은 [AI_OPERATIONS.md](AI_OPERATIONS.md)에 있다.

---

## 이 저장소가 무엇인가 — 한 문장

> **정본은 회사 PC의 Tampermonkey에서 지금 돌고 있는 코드다.
> 이 저장소는 그 사본을 받아 정규화·색인·검사하는 기계다.**

이 선언이 설계 전체를 결정한다.

저장소가 정본을 자처하면, 외부 AI 채팅에서 계속 작업하는 실제 흐름과 매번 충돌한다.
충돌하면 사용자는 저장소를 우회하고, 우회되는 저장소는 가치가 0이다.
그래서 저장소는 **막지 않고 검사만** 한다. 대신 왕복하면 파일이 나아져서 돌아오게 만든다.
그 이득이 이 구조의 유일한 추진력이다.

---

## 사용자가 하는 일 — 두 가지뿐

```
① 외부 AI 채팅에서 받은 .user.js 를 inbox/ 에 넣고 커밋한다. 파일명은 아무거나.
                              ↓  (봇이 자동 처리)
② 봇이 정리해서 scripts/<slug>.user.js 로 돌려주면 그걸 Tampermonkey에 덮어쓴다.
```

봇이 하는 일: 슬러그 판정 → 헤더 정규화(`@namespace`/`@name`/`@version`) → 프리앰블 주입 →
**본문은 바이트 한 글자도 건드리지 않음** → `scripts/`에 커밋 → 원본을 `archive/`에 보관 →
색인·충돌표·PII 리포트·계약 드리프트 재생성 → 결과를 커밋 메시지와 이슈에 남김.

## 트리

```
WAP/
├─ inbox/                 ★ 사용자가 손대는 유일한 디렉터리
├─ scripts/               ▲ 봇 생성물 = Tampermonkey에 붙여넣을 사본 (slug.user.js)
├─ archive/               반입 이전 원본 as-is (읽기 전용)
├─ lib/                   인라인 복제의 원본 (빌드 대상이 아니라 "복붙의 정본")
│   ├─ preamble.js            자기등록 + 전역 킬스위치 (약 15줄, 전 스크립트 필수)
│   └─ compare-core.js        대조 Helper 2종의 831줄 공통 코어
│
├─ contracts/             코드가 아니라 사실(fact). 여기가 이 저장소의 중심이다.
│   ├─ scripts.yaml           ★ slug ↔ namespace ↔ 표시명 ↔ 소유 자원  (사람이 쓰는 유일한 파일)
│   ├─ systems.yaml           호스트·포트·공통 아키텍처
│   ├─ endpoints.yaml         API 경로 + confidence + verifiedAt
│   ├─ status-codes.yaml      (화면ID, 필드명, 코드) → 의미.  전역 공통표 금지
│   ├─ screens.yaml           화면ID ↔ 목록API ↔ 셀→팝업 라우팅
│   ├─ write-guard.yaml       쓰기 차단 정규식의 유일한 원본
│   ├─ keymap.yaml            VIA / AutoHotkey / Tampermonkey 3층 전체
│   └─ bridge/                manifest.schema.json · bridge-api.md
│
├─ rules/                 JS와 Python이 같은 파일을 읽는 분류 규칙 (데이터)
├─ state/                 ▲ 전부 자동 생성. 사람이 손대지 않음
│   ├─ INDEX.md               slug·표시명·버전·반입일 한눈표
│   ├─ pages.md               URL → 동시 실행 스크립트 목록
│   ├─ collisions.md          전역·GM키·DOM id·단축키·z-index 충돌
│   ├─ pii-report.md          위치만. 값은 기재하지 않음
│   ├─ drift.md               계약 ↔ 코드 리터럴 불일치
│   ├─ outline/<slug>.md      섹션 지도 (거대 파일을 통째로 안 읽기 위한 것)
│   └─ brief/<slug>.md        ★ GPT에 붙여넣을 고정 지시서
│
├─ twin/screens/          마스킹된 화면 골격만.  twin/raw/ 는 커밋 금지
├─ corpus/law/            법령 조문 (조 단위 분할 + meta.json)
├─ manual/                인터랙티브 매뉴얼 (오프라인 정적 HTML) + 화면-법령 매핑
├─ python/                bridge/ (manifest 생산자) · reports/ (xlsx·보고서)
├─ vendor/                xlsx · pdf.js · mammoth 버전 고정 반입본 + CHECKSUMS
├─ tools/                 guard.py · check_registry.py · import · index · drift
└─ tests/fixtures/sanitized/
```

폴더가 늘었다. 앞선 안(폴더 2개)에서 바뀐 이유는 단순하다 —
**성격이 다른 물건이 섞여 있으면 게이트를 다르게 걸 수 없기 때문**이다.
`twin/raw`는 절대 커밋 금지, `corpus/`는 커밋 필수, `state/`는 리뷰 대상 아님.
이건 취향이 아니라 검사 규칙의 단위다.

## 정체성 — 파일명을 마음대로 바꿀 수 있게 하는 방법

**정체성 키는 파일명도 `@name`도 아니고 slug 하나다.**
`contracts/scripts.yaml`이 slug ↔ `@namespace` ↔ 표시명 ↔ 소유 자원을 선언하고,
봇이 이 파일을 근거로 반입 파일의 헤더를 다시 쓴다.

| 바꾸고 싶은 것 | 하는 일 | 비용 |
|---|---|---|
| 저장소 안 파일명 | **없음.** 경로는 slug가 정한다 | 0 |
| 표시명(`@name`) | `scripts.yaml`의 `displayName` 한 줄 | 저장소 1줄 + **Tampermonkey에 다시 붙여넣기 N회** |
| slug 자체 | `aliases:`에 옛 slug를 남긴다 | 이력은 유지 |

> **과장하지 않기.** 이름 변경은 저장소에서 1줄이지만, 매일 보는 Tampermonkey 목록이 바뀌려면
> 그 스크립트를 다시 붙여넣어야 한다. 저장소가 줄여주는 것은 **이력 추적과 충돌 검출**이지
> 붙여넣기 횟수가 아니다.

### Tampermonkey에서 데이터를 잃지 않는 규칙 세 가지

1. **새 버전은 반드시 편집기에서 덮어쓴다.** "새 스크립트 설치"로 넣으면
   `@name`이 같아도 별개 항목이 되어 GM 데이터가 갈린다.
2. **`@namespace`는 slug로 고정하고 그 뒤로 바꾸지 않는다.** 현재 4그룹이 중복이므로
   이 1회 정규화가 유일하게 위험한 순간이다 → GM 데이터가 쌓인 3개
   (`core-recon`·`portal-dashboard`·`mail-gwx`)는 **변경 전에 GM 값 내보내기를 먼저 넣는다.**
3. **잃으면 곤란한 상태는 GM에서 뺀다.** GM 저장소는 (namespace, name)에 종속되지만
   `localStorage`/IndexedDB는 오리진 스코프라 이름을 바꿔도 살아남는다.
   키는 `wap:<slug>:<name>`. `GM_setValue`는 **지워져도 되는 토글**에만 쓴다.

## 게이트 — 차단은 정확히 4개

검사 항목이 늘어나면 사용자는 반드시 우회한다. 그래서 **막는 것과 알리는 것을 분리**한다.

### 커밋을 막는 것 (4개 — 이 목록이 5개가 되는 날 이 구조는 실패한 것이다)

1. **PII·자격증명** — `tools/guard.py`
2. **구문 파손** — `node --check`
3. **구조 계약 파손** — `@namespace` 변경 · 프리앰블 부재 · 인라인 마커 쌍 불균형
4. **쓰기가드 위반** — `contracts/write-guard.yaml` 밖의 쓰기 호출

### 커밋은 되지만 **배포본을 새로 굽지 않는 것** (N개, 늘어나도 됨)

외부 CDN `@require` 추가 · `contracts/` 밖의 엔드포인트 문자열 · 인라인 블록 해시 불일치 ·
버전 미상승 · 계약 드리프트.

막히는 게 아니라 **붙여넣을 파일이 갱신되지 않을 뿐**이므로 우회할 유인이 없다.
이 두 층 분리가 "규칙이 늘어나 저장소를 안 쓰게 되는" 경로를 막는다.

### 검사기 공통 규칙 — 침묵을 성공으로 읽지 않는다

- **검사 대상 0개는 성공이 아니라 실패다.** 실제로 이 저장소에서 두 번 당했다
  (한글 파일명 → `guard.sh` 전부 통과, 글롭 미매칭 → CI 초록불).
- 검사 대상 개수는 글롭이 아니라 **레지스트리에서 뽑는다**(`tools/check_registry.py`).
  경로가 바뀌어도 검사가 조용히 꺼지지 않는다.
- 읽을 수 없는 파일은 통과가 아니라 실패다.
- `python3`나 `node`가 없어서 검사를 못 하면, 건너뛰지 말고 그 사실을 말한다.

## 거대 파일 — 쪼개지 않는다

6,505줄은 6,505줄로 둔다. 근거는 [FINDINGS §5](FINDINGS.md).

빌드를 안 하는 이유는 더 단순하다. **배포 경로가 복사·붙여넣기뿐**이므로
(`@updateURL`/`@downloadURL`이 17개 전부 0건) 빌드 산출물을 커밋해야만 쓸 수 있는데,
그러면 빌드는 "소스와 산출물이 어긋날 수 있는 상태"를 새로 만드는 것 말고 아무것도 하지 않는다.
사용자가 npm을 못 돌리므로 어긋남은 반드시 발생한다.

대신 세 가지를 한다.

1. **인라인 동기화 복제** — 831줄 공통 코어를 `lib/compare-core.js`로 승격하되
   두 파일 안에는 그대로 남기고 마커로 감싼다.
   ```js
   /* WAP-INLINE lib/compare-core.js@3 START */ … /* WAP-INLINE END */
   ```
   봇이 양쪽을 원본과 바이트 동일하게 유지한다. **파일은 언제나 그 자체로 완전하다.**
   마커 안이 원본과 달라지면 봇은 자동 수정하지 않고 **이슈를 연다** — 어느 쪽이 정본인지는 사람만 안다.
   나중에 진짜 모듈화가 필요해지면 이 마커가 그대로 모듈 경계가 된다.
2. **`state/outline/<slug>.md`** — 섹션 앵커·큰 함수·CSS 범위·노출 전역의 지도.
   AI가 6,505줄 대신 60줄을 읽고 필요한 구간만 부분 읽기 한다.
   좌표는 줄번호가 아니라 **파일 안 섹션 마커**를 기준으로 잡는다(줄번호는 한 번 수정하면 썩는다).
3. **변경이력 주석을 `changelogs/<slug>.md`로 복사**하고 파일 상단에는 최근 3건만 남긴다.
   `portal-dashboard`는 이것만으로 22% 줄어든다. 코드는 한 줄도 안 건드린다.

## 통계는 어디서 계산하는가 — 웹 vs Python

경계를 데이터로 표현한다(`rules/`).

| 웹(Tampermonkey)에서 한다 | Python에서 한다 |
|---|---|
| 한 화면·한 API에서 끝나는 집계 | 여러 소스를 매칭해야 하는 것 |
| 건수·합계·D-day·상태별 분류 | 퍼지 매칭, 이름 정규화, 다중 시트 |
| 목록을 표로 보여주고 CSV/클립보드로 내보내기 | 비용 대사, 연도별 보고서, 서식 있는 xlsx 생성 |
| **원자료를 내보내는 것까지** | **원자료를 받아 가공하는 것부터** |

판정 규칙 하나: **브라우저에서 xlsx를 굽지 않는다.**
지금은 `stats-patent`·`stats-ledger`가 SheetJS로 브라우저에서 굽고 있고,
그래서 외부 CDN 의존이 생겼다(§6). 웹은 JSON/CSV까지, xlsx는 Python이 만든다.

분류 규칙(적요 정규식·단계 매핑)은 현재 JS에 두 벌로 갈라져 있다.
이걸 `rules/*.json` 한 벌로 합쳐서 **JS와 Python이 같은 파일을 읽게** 한다.

## Python 연계 — 새로 설계하지 않는다

이미 매일 돌고 있는 것을 계약으로 승격시킨다(§8). 데이터 흐름은 **Python이 만들고 TM이 읽는** 쪽이다.

| 등급 | 방식 | 판단 |
|---|---|---|
| 1순위 | **폴더 경유** — File System Access API로 고른 결과 폴더 | 서버 없음. 이미 주경로. 가장 안전 |
| 2순위 | 다운로드 폴더에 놓고 읽기 | 수동 |
| 3순위 | **localhost 브리지**(`127.0.0.1:8765`) | 기존 것은 승인 범위로 인정·유지. **신규 확장만 사전 확인** |

금지가 아니라 등급이다. 앞서 커밋한 "localhost 금지" 규칙은 실작동 경로를 지우는 규칙이었다.

`contracts/bridge/manifest.schema.json`이 `jobs[]` 스키마의 유일한 원본이 되고,
다른 스크립트가 Python 산출물을 받고 싶으면 **새 통신 방식을 만들지 말고 같은 manifest 형태를 쓴다.**

## 디지털트윈 + 법령 인터랙티브 매뉴얼

**같은 저장소, 다른 등급.** 나누지 않는 이유는 트윈이 `contracts/screens.yaml`을
스크립트와 공유해야 하기 때문이다 — 분리하면 이미 갈라진 화면 계약이 한 벌 더 늘어난다.

```
정찰/수집  →  twin/raw/     (커밋 금지: .gitignore + guard 이중 차단)
                 ↓ tools/sanitize  (화이트리스트 방식)
          →  twin/screens/  (커밋: tag/id/name/type/컬럼순서/그리드ID 만)
                 ↓ 사람 확정
          →  contracts/screens.yaml
                 ↓
manual/mapping/screen-law.yaml   ← (화면ID, 필드ID) → 조문ID.  사람이 만드는 유일한 부분
                 ↕
corpus/law/<법령ID>/<조번호>.md  + meta.json (공포일 · **시행일** · 개정이력)
                 ↓
manual/src/   오프라인 정적 HTML (내부망에서 AI API 불가 → n-gram 역색인)
```

- **스크린샷 이미지는 금지.** 마스킹을 검증할 방법이 없다.
- **저장소는 private 고정.** CI가 visibility를 조회해 public이면 실패시킨다(문장이 아니라 기계).
- **법령 조문은 원문을 커밋한다.** 저작권법 제7조로 보호 대상이 아니다.
  단 **판례·해설·주석서는 금지** — 링크와 인용만. PDF도 금지, 텍스트만.
- **시행일은 1급 정보다.** 개정되면 매뉴얼이 통째로 틀려진다. 조 단위로 쪼개는 이유도 이것이다
  — 개정되면 바뀐 조만 diff에 뜬다.

실측상 17개 스크립트 전체에 법령 조문 참조는 **0건**이다. 이 영역은 완전 신규이고, 그래서 마지막이다.

## 이 구조가 실패한다면

정직하게, 가능성 높은 순서로.

1. **사용자가 `inbox/`를 안 쓴다.** 외부 AI에서 받아 곧장 TM에 붙여넣고 끝낸다.
   저장소는 6개월 뒤 구버전 17개의 무덤이 되고, 그 위에 쌓인 계약이 낡은 사실을 말하게 된다.
   낡은 계약을 근거로 AI가 코드를 고치면 **지금보다 나빠진다.**
   → 징후: `state/`의 반입일이 3개월 이상 정지. 그때는 저장소를 접고 `contracts/`만 남기는 게 정직하다.
2. **D5/D7의 붙여넣기 날에 멈춘다.** 17개를 다시 붙여넣다가 하나가 깨져 그날 업무가 멈추면
   저장소 전체를 불신하게 된다. → 위험 낮은 순서로, 편집기 in-place 교체로, 되돌리기는 옛 내용 재붙여넣기.
   그리고 **프리앰블이 없는 스크립트도 그냥 돌게** 만들어 중간에 멈출 수 있게 한다.
3. **봇이 파일을 망가뜨린다.** 매일 쓰는 스크립트의 헤더를 자동으로 고치는 것 자체가 위험이다.
   → 본문 바이트 불변 보장 + 헤더 블록만 편집 + `node --check` + 본문 SHA 대조 + `archive/`에 원본 무조건 보관.
   그래도 확률은 0이 아니다.
4. **`contracts/`가 낡는다.** 코드가 계약을 런타임에 읽지 않으므로 계약은 문서로만 남고,
   드리프트 리포트가 소음이 되면 사람은 무시한다. 이 구조의 가장 조용한 실패 지점이다.
